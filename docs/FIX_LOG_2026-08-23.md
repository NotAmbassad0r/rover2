## Known, deliberately deferred (decisions, not omissions)

### D1 (CRITICAL, code review) — Port 8082 has no authentication

`pi/server.py:213-218,742-746`: every REST route (77 of them) and the `/ws` WebSocket endpoint accept any caller — no auth dependency, header check, or token comparison anywhere in `pi/server.py`. CORS is `allow_origins=["*"]`. The WebSocket's `ws_endpoint` calls `websocket.accept()` unconditionally with no `Origin` inspection. Anyone who can reach the IP can drive the robot, enable autonomous FOLLOW, edit config via `POST /api/config/tuning`, run scripts, reset the watchdog's action budget, and reach the full 35-tool LLM agent. Camera port 8081 (`pi/camera_server.py:218-227`, finding B5) has the same exposure on a separate, unauthenticated, plain-HTTP port.

**DECISION (2026-08-23): deliberately deferred.** Auth is currently low priority. This is valid **only** under a LAN-only / trusted-network assumption while the robot is in the build-and-test phase.

**TRIPWIRE** — this deferral is void, and D1 becomes highest priority, the moment **any** of these becomes true:
- The control port (8082) or camera port (8081) becomes reachable from outside the home LAN. **Note:** Tailscale already advertises the Pi — confirm it does not expose these ports externally.
- The robot is operated untethered / outside the home (the project's Phase D goal).
- Arm/gripper manipulation ships in a way that raises the stakes of unauthenticated physical-actuation control beyond what's already shipped.

This is recorded as a tracked decision with an explicit revisit trigger, not a silent gap. Cross-referenced in `PROJECT.md`'s existing auth-deferral line (line 25) so the two documents agree.
